# 08 · 文件系统与扩展

## 什么是 FileSystem

FileSystem 是 YooAsset 的**物理文件 IO 抽象层**，它屏蔽了不同平台/场景下的文件读写差异。所有的：

- Bundle 文件的下载、存储、读取
- Manifest 的加载
- 版本号的查询
- 缓存清理

都通过 `IFileSystem` 接口来完成，框架内置了 6 种实现，也支持自定义扩展（微信小游戏就是扩展的 FileSystem）。

---

## 内置 FileSystem 总览

| 实现类 | 对应运行模式 | 根目录 |
|--------|------------|--------|
| `DefaultEditorFileSystem` | EditorSimulateMode | 构建模拟输出目录 |
| `DefaultBuildinFileSystem` | OfflinePlayMode / HostPlayMode 首包 | `Application.streamingAssetsPath` |
| `DefaultCacheFileSystem` | HostPlayMode 缓存 | `Application.persistentDataPath` |
| `DefaultUnpackFileSystem` | 内置包解压 | `Application.persistentDataPath` |
| `DefaultWebServerFileSystem` | WebPlayMode 本地 | WebServer 根目录 |
| `DefaultWebRemoteFileSystem` | WebPlayMode 远端 | CDN 服务器 |

## FileSystemParameters（文件系统参数）

`FileSystemParameters` 是创建文件系统的配置对象，通过**反射**实例化对应的 `IFileSystem`：

```csharp
// 内部核心逻辑
var type = Type.GetType(parameters.FileSystemClass);
var fs   = (IFileSystem)Activator.CreateInstance(type);
```

**内置工厂方法**（最常用）：

```csharp
// 编辑器模拟模式
FileSystemParameters.CreateDefaultEditorFileSystemParameters(packageRoot);

// 内置文件系统（StreamingAssets）
FileSystemParameters.CreateDefaultBuildinFileSystemParameters();

// 缓存文件系统（联机模式，需传入 IRemoteServices）
FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices);

// 解压文件系统（内置包自动解压到可写目录）
FileSystemParameters.CreateDefaultUnpackFileSystemParameters();

// WebGL 服务器
FileSystemParameters.CreateDefaultWebServerFileSystemParameters();

// WebGL 远端
FileSystemParameters.CreateDefaultWebRemoteFileSystemParameters(remoteServices);
```

**传入自定义参数**：

```csharp
var fsParams = FileSystemParameters.CreateDefaultCacheFileSystemParameters(remoteServices);

// 指定解压根目录（v2.3.18 新增）
fsParams.AddParameter(FileSystemParametersDefine.UNPACK_FILE_SYSTEM_ROOT,
    Application.persistentDataPath + "/MyUnpackCache");

// 超时时间（秒）
fsParams.AddParameter(FileSystemParametersDefine.DOWNLOAD_TIMEOUT, 60);
```

## IFileSystem 接口详解

实现自定义 FileSystem 需要实现以下方法：

```csharp
internal interface IFileSystem
{
    string PackageName { get; }   // 所属包裹名
    string FileRoot    { get; }   // 文件根目录
    int    FileCount   { get; }   // 管理的文件数量

    // === 异步操作（返回对应的 Operation） ===

    // 文件系统初始化（挂载、校验内置资源等）
    FSInitializeFileSystemOperation  InitializeFileSystemAsync();

    // 查询最新版本号（从服务器或本地）
    FSRequestPackageVersionOperation RequestPackageVersionAsync(bool appendTimeTicks, int timeout);

    // 加载指定版本的 Manifest
    FSLoadPackageManifestOperation   LoadPackageManifestAsync(string packageVersion, int timeout);

    // 下载单个 Bundle 文件
    FSDownloadFileOperation          DownloadFileAsync(PackageBundle bundle, DownloadFileOptions options);

    // 加载 Bundle 文件到内存（返回 AssetBundle 或原生字节）
    FSLoadBundleOperation            LoadBundleFile(PackageBundle bundle);

    // 清理缓存文件
    FSClearCacheFilesOperation       ClearCacheFilesAsync(PackageManifest manifest, ClearCacheFilesOptions options);

    // === 同步方法 ===

    void SetParameter(string name, object value); // 接收初始化参数
    void OnCreate(string packageName, string packageRoot); // 创建时调用
    void OnDestroy();                              // 销毁时调用

    bool Belong(PackageBundle bundle);  // 判断 Bundle 是否归属此 FS
    bool Exists(PackageBundle bundle);  // 判断文件是否本地存在
    bool NeedDownload(PackageBundle bundle); // 是否需要从远端下载
    bool NeedUnpack(PackageBundle bundle);   // 是否需要解压
    bool NeedImport(PackageBundle bundle);   // 是否需要导入（小游戏场景）
}
```

## 自定义 FileSystem（扩展示例）

以下是一个简化的自定义 FileSystem 骨架：

```csharp
public class MyCustomFileSystem : IFileSystem
{
    private string _packageName;
    private string _fileRoot;

    public string PackageName => _packageName;
    public string FileRoot    => _fileRoot;
    public int    FileCount   => 0; // 实现统计逻辑

    public void OnCreate(string packageName, string packageRoot)
    {
        _packageName = packageName;
        _fileRoot    = packageRoot;
    }
    public void OnDestroy() { }
    public void SetParameter(string name, object value) { /* 接收自定义参数 */ }

    public FSInitializeFileSystemOperation InitializeFileSystemAsync()
    {
        // 返回自定义的初始化 Operation
        return new MyInitOperation(this);
    }

    // ... 实现其他接口方法
}

// 注册方式：在 FileSystemParameters 构造时传入类型全名
var fsParams = new FileSystemParameters(
    typeof(MyCustomFileSystem).FullName + ", Assembly-CSharp",
    packageRoot);
```

## 微信小游戏 FileSystem 扩展（Mini Game Sample）

微信小游戏使用了自定义 FileSystem（`WechatFileSystem`）：
- 下载 → 使用微信 JSAPI `wx.downloadFile`
- 存储 → 微信的 `USER_DATA_PATH`（沙盒目录）
- 加载 → `wx.env.USER_DATA_PATH` 路径读取

```csharp
// 初始化参数中使用微信扩展 FileSystem
createParameters.WebServerFileSystemParameters =
    WechatFileSystemCreater.CreateFileSystemParameters(
        packageRoot: $"{WX.env.USER_DATA_PATH}/__GAME_FILE_CACHE",
        remoteServices: remoteServices);
```

## HostPlayMode 的双 FileSystem 架构

联机模式实际上挂载了**两个** FileSystem：

```
ResourcePackage (HostPlayMode)
  ├── BuildinFileSystem  → 读取 StreamingAssets 中的首包 Bundle
  └── CacheFileSystem    → 读取/写入 persistentDataPath 中的下载缓存
```

### 真实加载流程（基于源码）

框架通过 `PlayModeImpl.GetBelongFileSystem()` 按**注册顺序**遍历 FileSystem 列表（Buildin 先注册，Cache 后注册），找到第一个 `Belong(bundle) == true` 的就用它：

```csharp
// PlayModeImpl.cs:229
foreach (var fs in FileSystems)   // Buildin 先
    if (fs.Belong(bundle))
        return fs;                // 返回即停
```

**两个 FileSystem 的 Belong 行为完全不同**：

```csharp
// BuildinFileSystem.Belong：查首包 catalog
public bool Belong(PackageBundle bundle)
    => _wrappers.ContainsKey(bundle.BundleGUID);

// CacheFileSystem.Belong：保底，永远返回 true
public bool Belong(PackageBundle bundle)
    => true;
```

所以真实归属判定是：

1. **先问 Buildin**：这个 Bundle 的 `BundleGUID` 在首包 catalog 里吗？
   - 在 → Buildin 接手（加载首包资源）
   - 不在 → 拒绝，继续问下一个
2. **Cache 兜底**：Buildin 拒绝的所有 Bundle，都归 Cache 管（可能触发下载）

### 热更新是怎么工作的

**关键**：Bundle 按 hash 命名，CDN 推新版本时 hash 变了，`BundleGUID` 也就变了：

```
首包里的是 boss_hashA.bundle  → GUID = hashA → Buildin catalog 里有
CDN 推新版 boss_hashB.bundle  → GUID = hashB → Buildin catalog 里没有
                                                  ↓
                                             自动落到 Cache
                                                  ↓
                                             Cache.Exists = false
                                                  ↓
                                             触发下载到 persistentDataPath
                                                  ↓
                                             之后 Cache.Exists = true，直接读缓存
```

**所以热更新的底层机制是：新版 Bundle 的 GUID 在首包 catalog 找不到，被 Cache 兜底捕获并下载。** 不是"Cache 无脑优先"。
