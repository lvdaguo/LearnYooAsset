### Q2 · 10/10 🌟 **这题你想得比预期深**

你不但答对了两个 FileSystem 的职责，**还主动质疑"能不能合并成一个"** —— 这是技术直觉！而且你自己推理出的答案基本命中了真实原因：

你的猜测：
> "APK 里占用的存储会持续占用，复制出来反而浪费。"

✅ **正确！** 核心原因就是**只读 vs 可写**的路径差异：

| 路径 | 读写 | 说明 |
|------|------|------|
| `StreamingAssets`（APK 内 / iOS 安装包内）| **只读** | Android 上实际在 APK 压缩包里，不能写入 |
| `persistentDataPath`（用户数据目录）| **可写** | 用于存 CDN 下载的增量 Bundle |

**再补一个你没想到的点**：Android 上 StreamingAssets 里的文件**不能直接用 File API 读**（因为它在 APK 内），必须通过 `UnityWebRequest` 或 `AssetBundle.LoadFromFile(streamingAssetsPath + ...)` 读取。两个 FileSystem 的**实现机制**也不同。

如果合并成一个，既要处理 APK 内压缩文件，又要处理本地可写缓存，代码复杂度会爆炸。**分离是典型的单一职责原则**。

### Q3 · 9/10 ✅ 答得清楚，而且问得好

主/备 CDN 的调用时机都答对了。  
**你问的"再失败咋整"也是关键问题**：

当 Main 和 Fallback 都失败，会经历：
1. **重试 `failedTryAgain` 次**（`CreateResourceDownloader(10, **3**)` 中的 3 就是这个）
2. 都失败后，`DownloaderOperation` 状态变为 `Failed`
3. 触发 `DownloadErrorCallback` 和 `DownloadFinishCallback(Failed)`
4. **业务层决定怎么处理** —— 显示"下载失败"弹窗 + 重试按钮是最常见方案

Space Shooter Sample 里就是走这个套路：UI 显示重试按钮 → 用户点击 → 发事件让状态机重回 `FsmDownloadPackageFiles`。

### Q5 · 6/10 ⚠️ **答得浅了，没说出"为什么分包"的理由**

你描述了每个包的用途，但题目问的是 **"为什么分多个包而不是合并成一个"**。

合并成一个包会有什么问题？
1. ❌ **下载粒度粗**：玩家想玩主线但不玩 DLC1，一个包就必须全下（800MB 劝退用户）
2. ❌ **更新粒度粗**：主包改个 UI 文字，整个 Manifest 哈希变化，玩家被迫重下相关 Bundle
3. ❌ **无法独立版本管理**：语音包想单独迭代 v1 → v2，但不想触发主包版本号变动
4. ❌ **清单膨胀**：一个巨型 Manifest 加载慢、内存大

**分包的真正价值**：
- ✅ **独立下载** —— 玩家按需取
- ✅ **独立更新** —— 各自版本号，各自 Manifest
- ✅ **独立清理** —— 卸载 DLC 不影响主包缓存
- ✅ **并行构建** —— CI 可以多包并行打（大项目关键）

### Q6 · 3/10 ❌ **你说得对，文档这块写得太薄**

你反驳得有道理，我给你补上。

**`EditorSimulateModeHelper.SimulateBuild("DefaultPackage")` 做了什么**：

```
1. 读取 AssetBundleCollectorSetting 的配置（哪些资源归哪个 Group）
2. 在内存中（不实际打 Bundle 文件）生成一份"假 Manifest"
3. 把这份 Manifest 写到一个临时目录
4. 返回 buildResult.PackageRootDirectory = 这个临时目录路径
```

**为什么需要它**：  
编辑器模拟模式下**不打 Bundle 文件**（直接读 AssetDatabase），但框架运行需要一份 Manifest 告诉它"`Enemy` 这个地址对应哪个资源、属于哪个分组"。SimulateBuild 就是**快速生成这份 Manifest 的桥梁**。

**PackageRootDirectory 是啥**：一个临时目录（类似 `Library/YooAssetBuildCache/Simulate/...`），里面放着模拟生成的 Manifest 文件，`DefaultEditorFileSystem` 会从这个目录读 Manifest。

### Q7 · 2/10 ❌ **punt 了**

> "我的话应该会显式设置"

实用主义是好的，但问题本身还是要答：

**不设置 `SetDefaultPackage` 会怎样**：

```csharp
YooAssets.LoadAssetAsync<GameObject>("Enemy");   // ← 这种"省略 package"的调用
```

这种静态 API 内部会调 `_defaultPackage.LoadAssetAsync(...)`，如果 `_defaultPackage == null`：

查看源码 `YooAssetsExtension.cs`：
```csharp
private static ResourcePackage _defaultPackage;
// 静态 API 内部：
DebugCheckDefaultPackageValid();  // ← 这里会抛异常或断言失败
return _defaultPackage.LoadAssetAsync(...);
```

**所以**：调用会直接报错 / 抛 `NullReferenceException`。

**正确的两种用法**：

```csharp
// 用法 A：设了默认包，直接用静态 API
YooAssets.SetDefaultPackage(package);
YooAssets.LoadAssetAsync<GameObject>("Enemy");

// 用法 B：不设默认包，显式通过 package 实例调用
var package = YooAssets.GetPackage("MainPackage");
package.LoadAssetAsync<GameObject>("Enemy");
```

多包项目**强烈推荐用法 B**，避免误用默认包。
