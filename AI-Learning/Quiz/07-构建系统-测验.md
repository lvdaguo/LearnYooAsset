### Q1 · 10/10 ✅ 全对 + **反问得非常好**

**Package / Group / Collector** 完美。

**你的追问："为啥不是直接多搞一个 Group 出来？"**  
这题答案：
- **Group** = 逻辑分组单位，一个 Group 有自己的**激活规则**（`ActiveRuleName`，可按平台/版本开关整组）、**资源标签** (`AssetTags`)
- **Collector** = 路径级收集器，负责从某个路径扫描文件
- **同一个 Group 里的所有 Collector 共享 Group 的属性**（激活规则 + 标签）

所以分层原因：
```
Group: "UI资源"（统一打 "ui" 标签，Android 平台激活）
  ├── Collector: Assets/UI/Home     ← 两个路径都被当成 "ui" 标签
  └── Collector: Assets/UI/Battle       归属同一个 Group 的配置
```

如果每个路径都搞一个 Group，**每个都得重复配置标签和激活规则**，冗余。

#### 📖 Q1 标准答案

层级：`Package → Group → Collector`

### Q2 · 6/10 ⚠️ Q1 和 Q3 对，Q2 纠结

**对号入座标准答案**：

| 场景 | 类型 | 理由 |
|------|------|------|
| UI Prefab 直接 Load | `MainAssetCollector` ✅ | 生成地址，可被代码加载 |
| Shader 被多 Material 引用 | `StaticAssetCollector` | 打包但**不生成地址**（代码不直接 Load），被其他 Bundle 引用即可 |
| Texture 只被某 Prefab 引用 | **通常不需要单独配 Collector** | YooAsset 默认会**自动把依赖资源**打进依赖包 |

**澄清 Q2 的"为啥不是 Depend"疑问**：

- `StaticAsset` = "**我存在于 Bundle 里，但代码别直接找我**"。适合 Shader / 全局 Settings。
- `DependAsset` = "**我是共享资源，多个 Bundle 会引用我，把我打成公共 Bundle**"。适合被高频共享的小资源。

Space Shooter 用 Static 的原因：**只是希望 Shader 被打包但不成为用户入口**，不需要考虑"多个包共享"的问题，Static 更简单。

**Q3 你答"DependAssetCollector"** —— 其实在实际项目里，**这种"只被一个 Prefab 引用"的 Texture 根本不用单独配 Collector**，YooAsset 的依赖分析会自动把它打进 Prefab 所在的 Bundle。只有当 Texture 被**多个 MainAsset** 共享时，才考虑 Depend。

> **📖 Q2 标准答案**  
> - UI Prefab → `MainAssetCollector`  
> - Shader → `StaticAssetCollector`  
> - Texture（只被一个 Prefab 引用）→ **不用配**，框架自动处理

### Q4 · 10/10 🌟 **分析得非常到位**

冲突概率从高到低：`AddressByFileName > AddressByGroupAndFileName > AddressByFilePath` ✅

**你的反问："space shooter 是啥？一般用啥？"**：

Space Shooter 用的是 **`AddressByFileName`**（你能看到地址是 `"UIHome"`、`"player_ship"` 这种短名字）。

为什么敢用最容易冲突的？**因为 YooAsset 有冲突检测**：
- 构建时如果检测到两个资源生成了**相同地址**，会直接**报错终止构建**
- 所以开发者必须保证文件名在项目内唯一

**两种风格之争**：

| 风格 | 优点 | 缺点 |
|------|------|------|
| `AddressByFileName`（短地址）| 业务代码干净（`"UIHome"` 比 `"Assets/UI/HomeWindow/UIHome.prefab"` 短）| 大项目命名压力大 |
| `AddressByFilePath`（全路径）| 零冲突，可重构路径 | 业务代码路径字符串长 |

**一般项目的选择**：
- 小项目 / demo → 短地址（`AddressByFileName`）
- 大项目 / 多人协作 → 全路径（`AddressByFilePath`）或 Group 限定（`AddressByGroupAndFileName`）

> **📖 Q4 标准答案**  
> 生成样式：`AddressByFileName` → `"Enemy"` / `AddressByFilePath` → `"Assets/Prefabs/Enemy.prefab"` / `AddressByGroupAndFileName` → `"GroupName/Enemy"`  
> 冲突风险：FileName > GroupAndFileName > FilePath  
> 实际选型：小项目 FileName，大项目 FilePath。YooAsset 构建时会检测冲突并终止

### Q6 · 7/10 ⚠️ 结构对了但平台层次位置不对

**YooAsset 的默认输出结构**（没有"平台"作为目录层）：

```
D:/CDN/                         ← BuildOutputRoot
└── Default/                    ← PackageName
    └── 1.0/                    ← PackageVersion
        ├── PackageManifest_Default_hashXXX.bytes
        ├── PackageManifest_Default_hashXXX.hash
        ├── catalog_Default_hashXXX.json
        └── xxxxxxx.bundle（按 Hash 命名的若干 Bundle 文件）
```

**平台是由 `BuildTarget` 参数决定的**，不会自动加到目录里。**你之前项目按平台分一级目录是 CI 脚本手动做的**（为了上传不同 CDN 分别管理），两种做法都合理。

实际很多团队会手动包一层：
```
D:/CDN/Android/Default/1.0/...
D:/CDN/iOS/Default/1.0/...
```

**但这是 CI 脚本的事，不是 YooAsset 默认行为**。

> **📖 Q6 标准答案**  
> ```
> BuildOutputRoot/PackageName/PackageVersion/
>   ├── PackageManifest_xxx_hash.bytes
>   ├── PackageManifest_xxx_hash.hash
>   ├── catalog_xxx_hash.json
>   └── 若干 xxx.bundle
> ```  
> **没有"平台"这一层目录**，平台由 `BuildTarget` 参数决定，按平台分目录是 CI 脚本手动加的。

### Q7 · 10/10 ✅ **思考得特别细**

你选对 3 个配置，且思考到"零安装包也得有登录 UI"这个**超关键的工程细节**！

**答案补充**：

零安装包方案里，你担心的**登录 UI / 更新进度 UI** 一般放在 **`Assets/Resources/`** 下，而不是 YooAsset 的 Collector 里。Resources 是 Unity 的老资源系统，**永远会打进主包**（APK/IPA），独立于 YooAsset。

所以经典的零安装包方案长这样：
```
Assets/
  ├── Resources/
  │     ├── LoginWindow.prefab    ← 打进首包
  │     └── PatchWindow.prefab    ← 打进首包（热更新 UI）
  └── GameRes/                    ← 走 YooAsset 管理
        └── ...（走 CDN 下载）
```

Space Shooter 的 Boot.cs 里就是这么做的：
```csharp
var go = Resources.Load<GameObject>("PatchWindow");  // ← Resources 加载
GameObject.Instantiate(go);
```

> **📖 Q7 标准答案**  
> - 零安装包 → `None`（登录/更新 UI 走 Resources）  
> - 全量首包 → `ClearAndCopyAll`  
> - 混合方案 → `ClearAndCopyByTags`（商业项目最常用）

### Q8 · 10/10 ✅ 虽然回看了文档，但会找就行

`UseAssetDependencyDB = true` 正确。

**这个参数的本质**：
- YooAsset 构建时需要分析**每个资源的依赖关系**（一个 Prefab 依赖哪些 Mesh/Material/Texture）
- 默认每次都从 AssetDatabase 重新计算，大项目（几万资源）可能要几分钟
- 开启这个后会**缓存依赖图**到磁盘，增量构建时直接读缓存，**速度能快 5-10 倍**

**商业项目必开**，没有理由关。

> **📖 Q8 标准答案**  
> ```csharp
> UseAssetDependencyDB = true,  // 缓存依赖图，大项目构建速度 5-10 倍
> ```
