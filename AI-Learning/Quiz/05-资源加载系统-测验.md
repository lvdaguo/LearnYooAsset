### Q2 · 10/10 🌟 **满分！一针见血**

> "应该把 loadasset 放在 for 外面吧，异步加载一次就可以了，然后 for 里同步的 instantiate"

完美答案。具体分析一下你踩到的点：

每次 for 循环调 `LoadAssetAsync<GameObject>("enemy_ship")` 都会：
- 创建一个新的 `AssetHandle`
- **引用计数 +1**（但加载的是同一个资产，所以是同一个 Provider 被重复引用）
- 10 个波次 × 每波 10 个 = 100 个 Handle，每个都在 `_handles` 列表里

**OnDestroy 时虽然都 Release 了**，但运行期间你持有了 100 个冗余 Handle，造成：
- 内存占用（Handle 对象本身 + 列表）
- 如果 SpawnWave 被调 N 次而 OnDestroy 一次，泄漏会累积

**正确写法**：

```csharp
private AssetHandle _enemyHandle;

public IEnumerator Preload()
{
    _enemyHandle = YooAssets.LoadAssetAsync<GameObject>("enemy_ship");
    yield return _enemyHandle;
}

public void SpawnWave(int count)
{
    for (int i = 0; i < count; i++)
        _enemyHandle.InstantiateSync(transform);  // 一个 Handle 实例化 N 次
}

private void OnDestroy() => _enemyHandle?.Release();
```

> **📖 Q2 标准答案** `LoadAsset` 放 for 外面，只加载一次；for 里只调 `InstantiateSync` 复用同一个 Handle

- D) Host + 本地缓存有 → 直接读缓存 ❌
- E) Host + **Sync** + 资源本地没有 → **❌ 立即失败，不会等下载**

**你的 E 答案直觉对了一半**："同步如果要下载效果很差，会阻塞" —— 你担心会阻塞所以犹豫。**但实际上 YooAsset 的设计比你想的更保守**：**同步加载不会触发下载**，而是直接**返回 Failed 状态的 Handle**。

设计理由：
- 同步下载 = 主线程阻塞数秒（网络请求）→ 游戏直接卡死

- 业务方要先用 Downloader 把资源拉下来，再用 Sync 读

**工业界常见 pattern**：
```
关卡加载前 → package.CreateResourceDownloader(tags=["level1"]) 把 level1 资源拉全
           → 进关卡后，LoadAssetSync 可以无忧使用（保证本地都有）
```

> **📖 Q5 标准答案** 只有 C 触发（Host + 资源本地没有 + **Async**）。Sync 加载资源没下载时**直接返回 Failed**，不触发下载

### Q6 · 2/10 ❌ **这道是全卷最关键的题，你选错了**

你的答案："A 吧，就类似对象池吧" —— **A 不是对象池，B 才是**。

**A 的问题（不止一个）**：

```csharp
var handle = package.LoadAssetSync<GameObject>("bullet");  // 每秒 10 次！
handle.InstantiateSync(pos, rot);
// 不 Release
```

1. **每秒 10 次 Load**：即使 YooAsset 内部有缓存（Provider 去重），每次 Load 还是要：
   - 在 ResourceManager 查找 Provider
   - 创建新 Handle
   - 递增引用计数
2. **不 Release**：Handle 累积，引用计数累积；一秒 10 个 Handle，一局 5 分钟 = 3000 个 Handle
3. **你的"反复 Release 性能差"理由不成立** —— Release 就是改 int 引用计数，比 Load 快得多

**B 才是正确做法**：

```csharp
// 启动时加载一次，Handle 缓存起来
_bulletHandle = package.LoadAssetAsync<GameObject>("bullet");
yield return _bulletHandle;

// 开火时复用
_bulletHandle.InstantiateSync(pos, rot);  // 只 Instantiate，不 Load

// 销毁时 Release 一次
```

**B 的本质**：**Handle 是"资源引用凭证"，Instantiate 才是"生成实例"**。一张电影票可以坐进影院看 N 次同一部电影（同一个 Handle 实例化 N 次），你不需要买 N 张票。

**这是 AssetHandle 设计的核心理念** —— 务必记住。你在 Q8 里描述了这个模式（"assethandle只是一个prefab吧"），但 Q6 里没有代入过来。

> **📖 Q6 标准答案** **B 对**。预加载一次 Handle，`InstantiateSync` 复用 N 次。**Handle ≠ Instance**（一张票进影院 N 次，不用买 N 张票）

### Q7 · 8/10 ✅ 三者描述都对，漏答了一个小问

你对三个 API 的描述都准确。**但问题最后问"哪个会导致资源'突然丢失'"，你没答**。

答案：**`UnloadAllAssetsAsync()`**。因为它**强制卸载所有资源**，不管是否还有 Handle 持有。调用后游戏中已经用了资源的 GameObject（Texture/Material/Mesh）会变成 null，画面就会"白屏/黑屏/丢失"。

**使用场景对比**：

| API | 影响 | 场景 |
|-----|------|------|
| `handle.Release()` | 单个 Handle，引用计数 -1 | 最细粒度，平时都用这个 |
| `UnloadUnusedAssetsAsync()` | 全包，引用计数为 0 的 Bundle 会卸载 | 场景切换时调一下，清残余 |
| `UnloadAllAssetsAsync()` | **全包，不管用没用**，全部卸载 | **几乎只在关机/切登录号时用**，普通场景切换别用！ |

> **📖 Q7 标准答案** 影响范围：Release < UnloadUnused < UnloadAll。**UnloadAllAssetsAsync 会导致资源"突然丢失"**（强制卸载正在用的资源，GameObject 贴图变 null）

### Q9 · 10/10 🌟 **完美答案，直接命中真实 Bug**

> "第一次播放完被 release handle 了吧，具体看特效是怎么实现的"

**完全正确**。这个 Bug 在工业项目里叫 "Texture Missing" 或 "白模问题"，根本原因是 **GameObject 生命周期 > Handle 生命周期**。

**典型错误代码**：

```csharp
// ❌ 错误写法
public IEnumerator PlayExplosion(Vector3 pos)
{
    var handle = YooAssets.LoadAssetAsync<GameObject>("explosion");
    yield return handle;
    var go = handle.InstantiateSync(pos);
    yield return new WaitForSeconds(1f);
    Destroy(go);
    handle.Release();   // ← 这里 Release 后，Bundle 可能被卸载
}                       //   第二次再 Load 时，如果 Bundle 还没加载完，就白了
```

**正确做法**：
- **特效 Handle 场景生命周期持有**（等同于对象池的做法）
- 或者用 `AutoUnloadBundleWhenUnused = false`（默认就是 false），让 Bundle 不会自动卸载，手动在场景退出时清

> **📖 Q9 标准答案** 首先怀疑：**Handle 被提前 Release**。第一次播放完 Release → Bundle 被卸载 → Texture 变 null → 白模/粉紫。修法：Handle 场景生命周期持有，不要每次播放完就 Release
