### Q4 · 7/10 ⚠️ **方向对了但范围说窄了**

你的答案："实现不同**操作系统**的文件读写..."

**问题**：`IFileSystem` 的抽象**不只是 OS 层面**，而是抽象了**所有数据来源的差异**：

| 差异维度 | 对应 FileSystem |
|---------|----------------|
| 编辑器 vs 运行时 | DefaultEditorFileSystem vs DefaultBuildinFileSystem |
| 本地 vs 远端 | DefaultBuildinFileSystem vs DefaultCacheFileSystem |
| PC/手机 vs WebGL | DefaultCacheFileSystem vs DefaultWebServerFileSystem |
| 常规平台 vs 小游戏 | 默认实现 vs 微信/抖音扩展（因为小游戏只能用 wx.downloadFile 这种 JSAPI，不能用普通 File API） |

所以抽象的**根本原因**：**不同场景的文件 IO 逻辑差异巨大**（不是仅仅 OS 差异）。

### Q6 · 8/10 ✅ 答得很好！

你答的三个要素：
- 资源大小 ✅
- md5 值（实际是 **hash + CRC**，但概念对）✅
- 资源名/路径 ✅

**唯一漏掉**：**依赖关系表**。这个是 AssetBundle 最关键的元数据 —— 一个 Prefab 可能依赖 3 个 Texture、2 个 Material，加载时必须先加载依赖包。没有依赖关系表，边玩边下载根本跑不起来。

**完整答案**：
```
PackageManifest
  ├── PackageAsset[]    (address → bundleId)  ← 地址到包的映射
  └── PackageBundle[]   (bundleId, hash, crc, size, deps[])  ← 包元数据 + 依赖
```

为什么是热更新核心：**比较本地 Manifest 和服务器 Manifest，差异就是要下载的 Bundle 列表**。

## 📖 标准答案一览

**Q1. 对象关系图**：
```
YooAssets (静态)
  └ ResourcePackage
        ├ IPlayMode
        │   └ IFileSystem
        ├ IBundleQuery
        └ ResourceManager
              └ Handle (AssetHandle/SceneHandle/RawFileHandle/SubAssetsHandle/AllAssetsHandle)
```

**Q2. YooAssets 和 ResourcePackage 的职责**：
- **YooAssets**：管理多 Package 的生命周期；创建 `YooAssetsDriver`；每帧驱动 `OperationSystem.Update()`
- **ResourcePackage**：一个包 = 一组 Bundle + 一份 Manifest；持有 ResourceManager / IPlayMode / IBundleQuery；对外暴露所有用户 API

**Q3. GameAsyncOperation**：
- 所有异步操作的基类（InitPackage、LoadAsset、Downloader 都继承它）
- 由 `OperationSystem` 每帧驱动 `InternalUpdate()`
- 支持协程 / 回调 / UniTask 三种等待
- 用户可继承写自定义异步任务（如 Sample 的 `PatchOperation`）

**Q4. IFileSystem 的作用**：
- 抽象所有"数据来源的差异"（不只是 OS 差异）
- 涵盖：编辑器 vs 运行时、本地 vs 远端、常规平台 vs 小游戏
- 内置 6 种实现，支持自定义扩展

**Q5. 引用计数场景**：
- 两次 Load 同一资源 → Bundle 引用计数 = 2
- `handle1.Release()` → 计数 = 1（>0，不卸载）
- 要 `handle2.Release()` 后计数归 0，Bundle 才卸载

**Q6. Manifest 的内容**：
```
PackageManifest
  ├── PackageAsset[]    (address → bundleId)
  └── PackageBundle[]   (bundleId, hash, crc, size, deps[])
```
**为什么是热更新核心**：比较本地/服务器两份 Manifest 的差异 = 需要下载的 Bundle 列表。**关键字段是依赖关系表**。

**Q7. 三种等待方式**：

| 方式 | 代码 | 场景 |
|------|------|------|
| 协程 | `yield return op` | MonoBehaviour 内最自然 |
| 回调 | `op.Completed += ...` | fire-and-forget、并发多任务 |
| UniTask | `await op.ToUniTask()` | 新项目首选，支持 try/catch |
