# 07 · 构建系统（Editor）

## 整体流程

```
配置 Collector（哪些资源打成哪些包）
        ↓
选择 BuildPipeline 和 BuildParameters
        ↓
BuildRunner 按顺序执行 IBuildTask 列表
        ↓
输出 Bundle 文件 + PackageManifest
        ↓
上传到 CDN（HostPlayMode）或复制到 StreamingAssets（OfflinePlayMode）
```

---

## 第一步：AssetBundle Collector 配置

### 配置层级结构

```
AssetBundleCollectorSetting（ScriptableObject）
  └── Package（包裹，对应运行时的 ResourcePackage）
        └── Group（分组，便于管理，可按平台/功能分组）
              └── Collector（收集器，指定一个路径或文件）
```

**打开入口**：`Window → Asset Management → YooAsset → AssetBundle Collector`

### 收集器（Collector）关键配置

| 配置项 | 作用 |
|--------|------|
| `CollectPath` | 要收集的文件夹或文件路径 |
| `CollectorType` | 见下表 |
| `AddressRule` | 资源定位地址生成规则 |
| `PackRule` | 打包策略（如何分组到 Bundle） |
| `FilterRule` | 过滤哪些文件不参与打包 |
| `AssetTags` | 资源标签（用于分包下载） |

### CollectorType（收集器类型）

**核心认知**：**"打包" 和 "可被代码加载" 是两件独立的事**。

| 类型 | 进 Bundle | 有 address（代码可 Load）| 打包条件 |
|------|----------|------------------------|---------|
| `MainAssetCollector` | ✅ 是 | ✅ 是（写入资源清单）| 无条件 |
| `StaticAssetCollector` | ✅ 是 | ❌ 否（不写入清单）| 无条件（只要扫到就打）|
| `DependAssetCollector` | 视引用情况 | ❌ 否（不写入清单）| **有条件**：只有被 MainAsset 引用才打 |

**类比**（C++ 可见性）：
- `MainAsset` = `extern` 函数，外部可调用
- `StaticAsset` = `static` 函数，存在于二进制但不暴露符号
- `DependAsset` = 纯依赖库，没人调用就被链接器优化掉

### 典型用法

- **MainAssetCollector** —— Prefab / 场景 / 配置，代码要 Load 的主资源
- **StaticAssetCollector** —— Shader / 全局 Settings / 字体（要无条件进包但代码不直接 Load）
- **DependAssetCollector** —— 资源库（只打被引用的，自动瘦身），少用，大多数依赖资源框架会自动分析

### 关于 Shader 的特殊处理

纯依赖分析处理 Shader 有**盲区**：
- `Shader.Find("xxx")` 代码动态加载，构建时扫不到
- URP/HDRP 的 Shader Variant Stripping 会激进剥离"看似没用"的变体
- 运行时动态创建 Material、后处理、RenderFeature 引用的 Shader

**YooAsset 的内置方案**：Collector 窗口 "Package Settings" 里的 **"Auto Collect Shaders"**（默认开启），会自动把项目里所有 Shader 收集进一个共享 Bundle。

**更严格的防御式做法**：显式配 `StaticAssetCollector` + `PackShaderVariants`，结合 Shader Variant Collection（SVC）。Space Shooter Sample 用的就是这种做法。

### 内置 PackRule（打包规则）

| 规则类名 | 说明 |
|----------|------|
| `PackSeparately` | 每个资源单独一个 Bundle（精细控制） |
| `PackDirectory` | 同目录下资源打成一个 Bundle（最常用） |
| `PackTopDirectory` | 按顶层目录打包 |
| `PackCollector` | 整个 Collector 下的资源打成一个 Bundle |
| `PackRawFile` | 原生文件打包（不经过 AB 压缩） |
| `PackShaderVariants` | Shader Variants 专用打包规则 |

### 内置 AddressRule（地址规则）

| 规则类名 | 生成的地址示例 |
|----------|--------------|
| `AddressByFileName` | `Enemy`（文件名，无扩展名） |
| `AddressByFilePath` | `Assets/Prefabs/Enemy.prefab`（完整路径） |
| `AddressByGroupAndFileName` | `Prefabs/Enemy` |

## 共享资源自动分析（重要）

**问题**：一张 Texture 被 10 个 Prefab 共享。如果各个 Prefab 的 Bundle 各自带一份，CDN 上会有 10 份拷贝 → 资源冗余。

这是 AssetBundle 系统的老难题 —— 资源引用关系是**图（DAG）**，但 Bundle 只能是**树**。

### YooAsset 的解决方案：EnableSharePackRule

`BuildParameters` 里开两个开关即可：

```csharp
buildParameters.EnableSharePackRule = true;         // 自动识别共享资源
buildParameters.SingleReferencedPackAlone = true;   // 单引用资源也独立打包
```

**效果**：构建时自动分析所有 MainAsset 的依赖：
- 被 2+ 个 MainAsset 引用的资源 → 自动打到**共享 Bundle**
- 只被 1 个 MainAsset 引用 → 打进那个 MainAsset 的 Bundle

### 共享资源处理的推荐顺序

1. **优先：自动分析**（`EnableSharePackRule = true`）—— 最省事
2. **不满意时：手动拆分** —— 如果自动结果的包大小 / 数量不理想（太碎或太大），再用 `DependAssetCollector` 手动管理
3. **极端场景：StaticAssetCollector** —— 无条件强制打包（哪怕没引用），很少用

### 三种处理方式对比

| 方式 | 打包条件 | 适用场景 |
|------|---------|---------|
| `EnableSharePackRule = true` | 框架自动分析共享资源 | **默认推荐**，大多数项目够用 |
| `DependAssetCollector` | 只打被 MainAsset 引用的 | 想显式管理共享资源目录 |
| `StaticAssetCollector` | 无条件全打 | 防御式（如 Shader 怕 `Shader.Find` 找不到）|

## 第二步：选择构建管线

### 四条构建管线对比

| 管线 | 类 | 适用场景 |
|------|----|---------| 
| **BuiltinBuildPipeline** | `BuiltinBuildParameters` | 传统 AB 打包，兼容性最好 |
| **ScriptableBuildPipeline** | `SBPBuildParameters` | 增量构建更快，需 SBP 包 |
| **RawFileBuildPipeline** | `RawFileBuildParameters` | 纯文件复制，不压缩 |
| **EditorSimulateBuildPipeline** | — | 生成模拟 Manifest，不打 Bundle |

## 第三步：构建参数（BuildParameters）

### 公共参数

```csharp
var buildParameters = new BuiltinBuildParameters();

// 输出目录（构建结果存放位置）
buildParameters.BuildOutputRoot = "D:/BuildOutput";
buildParameters.BuildinFileRoot = "Assets/StreamingAssets";

// 目标平台
buildParameters.BuildTarget = BuildTarget.Android;

// 包裹名和版本（版本号建议用日期或自增数字）
buildParameters.PackageName    = "DefaultPackage";
buildParameters.PackageVersion = "1.0.0";

// 是否清除构建缓存（增量构建时保持 false）
buildParameters.ClearBuildCacheFiles = false;

// 开启依赖缓存，加速资源收集（大项目强烈建议开启）
buildParameters.UseAssetDependencyDB = true;

// Bundle 文件名格式
buildParameters.FileNameStyle = EFileNameStyle.HashName; // 推荐 HashName

// 首包资源复制策略
buildParameters.BuildinFileCopyOption = EBuildinFileCopyOption.ClearAndCopyAll;
```

### BuiltinBuildPipeline 专属参数

```csharp
var buildParameters = new BuiltinBuildParameters();

// 压缩算法
buildParameters.CompressOption = ECompressOption.LZ4;  // LZ4 / LZMA / Uncompressed

// 加密服务（可选）
buildParameters.EncryptionServices = new MyEncryptionServices();
```

### RawFileBuildPipeline 专属参数（v2.3.18 新增）

```csharp
var buildParameters = new RawFileBuildParameters();

// 文件哈希值计算是否包含路径信息（默认 false）
buildParameters.IncludePathInHash = false;
```

## 第四步：执行构建

### 通过编辑器窗口

`Window → Asset Management → YooAsset → AssetBundle Builder`

### 通过代码（CI/CD 脚本化构建）

```csharp
using YooAsset.Editor;

public static class BuildScript
{
    [MenuItem("Build/Build Android")]
    public static void BuildAndroid()
    {
        var buildParameters = new BuiltinBuildParameters
        {
            BuildOutputRoot      = "D:/CDN",
            BuildinFileRoot      = "Assets/StreamingAssets",
            BuildTarget          = BuildTarget.Android,
            PackageName          = "DefaultPackage",
            PackageVersion       = DateTime.Now.ToString("yyyyMMdd_HHmmss"),
            FileNameStyle        = EFileNameStyle.HashName,
            BuildinFileCopyOption = EBuildinFileCopyOption.ClearAndCopyAll,
            CompressOption       = ECompressOption.LZ4,
            UseAssetDependencyDB = true,
        };

        var pipeline = new BuiltinBuildPipeline();
        var buildResult = pipeline.Run(buildParameters, enableLog: true);

        if (buildResult.Success)
            Debug.Log($"构建成功！输出路径：{buildResult.OutputPackageDirectory}");
        else
            Debug.LogError($"构建失败：{buildResult.ErrorInfo}");
    }
}
```

## 构建输出目录结构

```
BuildOutputRoot/
└── DefaultPackage/
    └── 1.0.0/                                  ← PackageVersion
        ├── PackageManifest_DefaultPackage_xxx.bytes  ← 资源清单（二进制）
        ├── PackageManifest_DefaultPackage_xxx.hash   ← 版本哈希文件
        ├── catalog_DefaultPackage_xxx.json           ← 可读清单（调试用）
        └── xxxxxxxxxxxxxxxxxxxxxxxx.bundle           ← Bundle 文件（hash命名）
```

将此目录上传到 CDN 对应路径即完成热更新部署。

## BuildinFileCopyOption（首包策略）

| 枚举值 | 说明 |
|--------|------|
| `None` | 不复制任何文件到 StreamingAssets |
| `ClearAndCopyAll` | 清空 StreamingAssets 后复制全部 Bundle |
| `ClearAndCopyByTags` | 按标签复制指定 Bundle 到 StreamingAssets |

**首包资源**：复制到 StreamingAssets 的 Bundle 会在安装包内，玩家无需下载直接使用。

## Task Runner 内部机制

构建系统内部是一个**管道（Pipeline）**模式，每条管线由一系列 `IBuildTask` 组成：

```csharp
// BuiltinBuildPipeline 内部大致执行顺序（TaskSetupBuildParameters 略）
1. TaskGetBuildMap        — 通过 Collector 收集资源，生成 BuildMapContext
2. TaskBuilding           — 调用 Unity BuildPipeline.BuildAssetBundles
3. TaskCreateManifest     — 生成 PackageManifest
4. TaskEncryption         — 加密 Bundle（如果配置了 EncryptionServices）
5. TaskCopyBuildinFiles   — 复制首包资源到 StreamingAssets
6. TaskVerifyBuildResult  — 验证构建结果（可选）
```

可通过继承 `IBuildTask` 并插入管线来**自定义构建步骤**（如自动上传 CDN）。
