# 02 · 核心原理与架构

## 整体分层

```
┌─────────────────────────────────────────┐
│              游戏业务代码                │  ← 你写的代码
├─────────────────────────────────────────┤
│         YooAssets (静态入口)            │  Runtime/YooAssets.cs
├──────────────┬──────────────────────────┤
│ ResourcePackage  │  OperationSystem      │  包管理 + 异步任务调度
├──────────────┼──────────────────────────┤
│ ResourceManager  │  DownloadSystem       │  加载调度 + 下载管理
├──────────────┼──────────────────────────┤
│    FileSystem (IFileSystem 接口)        │  物理文件读写抽象层
└─────────────────────────────────────────┘
```

## 核心对象关系

```
YooAssets (静态)
  └── ResourcePackage  (每个"包"一个实例)
        ├── IPlayMode          (当前运行模式的逻辑)
        │     └── IFileSystem  (文件系统，可自定义)
        ├── IBundleQuery       (Bundle 查询，由 IPlayMode 实现)
        └── ResourceManager   (Handle / Provider 管理)
              ├── AssetHandle
              ├── SceneHandle
              ├── RawFileHandle
              └── AllAssetsHandle
```

## 关键类职责

### YooAssets.cs
- **全局静态入口**，管理多个 `ResourcePackage` 的生命周期
- 创建驱动 GameObject（`YooAssetsDriver`），挂在 `DontDestroyOnLoad` 下
- 每帧驱动 `OperationSystem.Update()`

```csharp
YooAssets.Initialize();          // 创建驱动，启动 OperationSystem
YooAssets.CreatePackage("Pkg");  // 新建包
YooAssets.GetPackage("Pkg");     // 获取已有包
YooAssets.SetDefaultPackage(pkg);// 设置默认包（可省略包名调用）
YooAssets.Destroy();             // 销毁整个系统
```

### ResourcePackage.cs
- **一个资源包** = 一组 Bundle + 一份 Manifest
- 持有 `ResourceManager`、`IPlayMode`、`IBundleQuery`
- 对外暴露所有用户 API（InitializeAsync / LoadAssetAsync / CreateDownloader …）

### OperationSystem.cs
- **协程调度器**，负责驱动所有 `GameAsyncOperation` 的执行
- 所有异步操作（初始化、更新清单、下载、加载…）都是 `GameAsyncOperation` 的子类
- 每帧被 `YooAssetsDriver.Update()` 调用一次

```csharp
// 自定义异步操作（继承此类即可接入调度）
public class MyOperation : GameAsyncOperation
{
    protected override void OnStart()  { /* 启动逻辑 */ }
    protected override void OnUpdate() { /* 每帧逻辑，完成时设 Status */ }
    protected override void OnAbort()  { /* 中止逻辑 */ }
}
YooAssets.StartOperation(new MyOperation());
```

### FileSystem（IFileSystem）
- **抽象所有文件 IO**，内置 6 种实现
- 可自定义实现（微信小游戏扩展就是自定义 FileSystem）

| 实现类 | 对应场景 |
|--------|---------|
| `DefaultEditorFileSystem` | 编辑器模拟模式 |
| `DefaultBuildinFileSystem` | 内置资源（StreamingAssets） |
| `DefaultCacheFileSystem` | 联机模式本地缓存 |
| `DefaultUnpackFileSystem` | 内置包解压到可写目录 |
| `DefaultWebServerFileSystem` | WebGL 服务器模式 |
| `DefaultWebRemoteFileSystem` | WebGL 远端下载 |

## 异步操作模式（重要）

YooAsset 的所有异步都通过 `GameAsyncOperation` 统一调度，支持三种等待方式：

```csharp
// 1. 协程（最常用）
yield return operation;

// 2. 回调
operation.Completed += (op) => { Debug.Log(op.Status); };

// 3. UniTask（需引入 UniTask 扩展包）
await operation.ToUniTask();
```

状态枚举：`EOperationStatus.None / Processing / Succeed / Failed`

## 引用计数原理

每个 `AssetHandle` 内部维护一个 `ProviderOperation`：

```
Handle.Release()
  └── ProviderOperation.引用计数 - 1
        └── 引用计数 == 0 → Bundle 引用计数 - 1
              └── Bundle 引用计数 == 0 → 卸载 Bundle
```

**重要**：必须调用 `handle.Release()` 或 `handle.Dispose()`，否则 Bundle 永不卸载（内存泄漏）。

## Manifest（资源清单）

Manifest 是整个系统的"导航图"，包含：
- 所有资源的地址 → Bundle 映射
- 所有 Bundle 的 hash / CRC / 文件大小
- 依赖关系表

```
PackageManifest
  ├── PackageAsset[]    (address → bundleId)
  └── PackageBundle[]   (bundleId → hash, size, crc, deps[])
```

热更新的本质就是：**比较本地 Manifest 和服务器 Manifest，找出差异 Bundle，下载补全**。
